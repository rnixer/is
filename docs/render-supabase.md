# Render + Supabase (free trial deployment)

Keep your private notes in `apps/cms/.env.render` using the committed template
`apps/cms/.env.render.example`. The private file is gitignored and is not loaded
by local startup. It is a record of Render settings, not an automatic deployment:
copy the completed variables into Render Environment. Keep local settings in
`apps/cms/.env`. Before using Render's import feature, fill every required value
and preserve the secrets already generated by the Blueprint; do not import blanks
over existing keys. Never add the private file to Git with `git add -f`.

Local mode stays independent: `npm.cmd run dev` starts local PostgreSQL, Strapi,
and the frontend. `apps/storefront/.env` points to `http://127.0.0.1:1337`.
Do not replace local database credentials with production credentials.

Online mode: Vercel → Render Strapi → Supabase PostgreSQL. Uploaded images use
Supabase Storage through its S3-compatible API. No ngrok is required.

## 1. Supabase

Create a separate Free project for this store. Do not connect Strapi to another
app's existing public tables. Save its database password in your password manager.

Click Connect → Session pooler (IPv4, port 5432). Copy these values for Render:

Alternatively, paste the complete Session pooler URI into `DATABASE_URL` in
`.env.render` and Render Environment. Replace the password placeholder and
URL-encode special characters in the password. A nonempty DATABASE_URL takes
precedence over separate host/user/password fields. Keep DATABASE_SSL and CA.
The Blueprint requests separate fields initially; after creation you can add
DATABASE_URL in Render Environment instead. Never share the completed URI.

- `DATABASE_HOST`: session pooler hostname, not the project HTTPS URL.
- `DATABASE_USERNAME`: the full username shown, usually `postgres.PROJECT_REF`.
- `DATABASE_PASSWORD`: database password, not an anon/service-role key.
- `DATABASE_NAME`: `postgres`.
- `DATABASE_SSL_CA`: full PEM server root certificate from Database settings,
  including BEGIN/END lines and actual newlines. TLS certificate verification stays enabled.

Do not choose Transaction pooler port 6543: this backend uses transactions,
schema synchronization and PostgreSQL session/advisory locking.

Under Storage, create a **public** bucket `product-images` for public product
photos only. Keep customer/order data in the database, not in this public bucket.
Under Storage S3 configuration generate server-only S3 credentials. Copy:

- `S3_ENDPOINT`: exact S3 endpoint from the Dashboard.
- `S3_REGION`: region from the same S3 configuration.
- `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY`: S3 credentials (not API keys).
- `S3_BUCKET`: `product-images`.
- `S3_PUBLIC_URL`: `https://PROJECT_REF.supabase.co/storage/v1/object/public/product-images`
  with no trailing slash.

## 2. Render

Commit/push the prepared changes. In Render choose New → Blueprint, connect
`rnixer/is`, select the branch and use root `render.yaml`. The service is explicitly
Free and creates no paid database or disk. Fill the fields from step 1.
The Blueprint generates unique Strapi secrets and `STOREFRONT_TOKEN`; keep those
values stable across redeploys. Render provides its own PORT. Public URL is
automatically taken from RENDER_EXTERNAL_URL.

If using New → Web Service manually instead:

- Repository root directory: leave blank (npm workspace dependencies are needed).
- Runtime: Node; Node version 24.18.0; Instance type: Free.
- Build: `npm ci && npm run build -w @igh/cms`.
- Start: `npm run start:render`.
- Health check: `/_health`.
- Copy all variables from render.yaml; generate strong secrets for generateValue entries.

Open `https://YOUR-SERVICE.onrender.com/admin` and create the online owner account.
Test an image upload and reload the Media Library. The file must appear in the
Supabase bucket and remain available after a Render restart.

## 3. Move existing products and files

Do not expect deployment to copy the Windows database or local uploads. Keep a
pg_dump backup and a backup of `apps/cms/public/uploads` before transferring.

For a NEW, EMPTY destination only, use Strapi's data transfer tool. Both instances
must run the same commit/schema. The transfer replaces destination content/files;
never run it against an existing live shop without a separate reviewed migration.

1. On the online Strapi Admin, create a Push transfer token in Settings → Transfer Tokens.
2. Stop local Strapi (Ctrl+C), leave local PostgreSQL running.
3. From repository root run:

```powershell
npm.cmd run strapi -w @igh/cms -- transfer --to https://YOUR-SERVICE.onrender.com/admin
```

4. Enter the transfer token at the interactive prompt, not in a committed command.
   Review the destination replacement confirmation before accepting.
5. Check product/variant counts, published states, prices and image formats online.
   Confirm image URLs point to Supabase Storage rather than `/uploads` on Render.
6. Revoke the transfer token, then restart local development if needed.

Admin accounts/tokens are not copied by the content transfer. The online owner
account is separate. Local and online databases do not automatically synchronize.
Do not transfer local test orders into a live-payment environment.

## 4. Vercel

Set Production variables, then redeploy:

- `STRAPI_URL=https://YOUR-SERVICE.onrender.com` (no `/admin` or `/api`).
- `STOREFRONT_TOKEN`: copy from the Render service, not the local CMS.
- `SITE_URL=https://is-mix14.vercel.app`.

No database passwords or S3 credentials belong on the frontend. Test the shop
and images on a phone with the Windows backend stopped: online must work independently.

## Free plan limits and payments

### Stripe Checkout + PromptPay activation

The existing checkout creates a one-time THB session for PromptPay/cards and
server-computed shipping of 30 THB per order. Payment is confirmed only by the
verified Stripe webhook and authoritative session, not the browser success page.

On the shop owner's Thai Stripe account, complete live account/business verification,
bank payout details, and enable PromptPay in payment method settings. Do not use
the developer's personal account for someone else's store payouts.

In Stripe Workbench/Webhooks, create an HTTPS destination:
`https://YOUR-SERVICE.onrender.com/api/stripe/webhook` for events:

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`

First verify sandbox events, failed/cancelled checkout, retries, stock reservation
expiry and duplicated webhook events on the deployed backend. For live mode,
set Render `STRIPE_MODE=live`, `STRIPE_SECRET_KEY=sk_live_...`, and the signing
secret `STRIPE_WEBHOOK_SECRET=whsec_...` belonging to the LIVE destination.
Redeploy, then run a small real purchase and check Stripe payment status, the
Strapi order total/shipping, stock consumption and the customer's status page.
Publishing code alone does not activate the Stripe account or payment methods.
Never paste secret keys into chat, GitHub or Vercel browser variables.

PromptPay uses a QR payment in a participating bank app; it is not a guarantee
that every mobile browser will open the banking app automatically. Test on the
owner's target Android/iPhone devices. Stripe transaction fees apply to real payments.

Live checkout should wait until always-on backend operation is addressed. Free
hosting is useful for sandbox validation but cannot guarantee timely background jobs.

Render Free sleeps after 15 idle minutes and can take about a minute to wake.
The current storefront request times out after 30 seconds, so the first visitor
may need to retry after wake-up. Background reconciliation cannot run while the
service is asleep; webhook delivery may be delayed. This is a TEST deployment,
not a promise of uninterrupted checkout. Keep STRIPE_MODE=test until payment
delivery, reconciliation and always-on hosting are verified.

Supabase Free has database/storage/egress limits and may pause inactive projects.
Monitor Usage and retain independent backups. Vercel Hobby is restricted to
personal non-commercial usage; check the appropriate plan before opening sales.
